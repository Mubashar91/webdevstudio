## 2. llms.txt — Present and Well-Formed

`https://www.webdevstudio.me/llms.txt` exists, is generated by `scripts/prerender.mjs`, and follows the informal llms.txt convention reasonably well: an H1 + one-line summary, then grouped sections (`## Pages`, `## Articles`, `## Case Studies`, `## Contact`) each as a markdown link list with a one-line description per entry. It's in sync with the sitemap (8 top-level pages, 13 articles, 6 case studies all present and matching live URLs).

**Important caveat, stated explicitly so it isn't overstated elsewhere in this audit:** llms.txt is a voluntary, unstandardized convention. It is **ignored by Google Search** (confirmed — Google has stated Gemini/Search do not consume it), and no major AI platform (OpenAI, Anthropic, Perplexity, Microsoft) has publicly committed to using it as a ranking or citation input as of this audit. Its practical value today is: (a) a cheap, low-risk hygiene file that costs nothing to maintain since it's auto-generated, and (b) a plausible-but-unproven aid for tools like ChatGPT's browsing/search mode that may fetch it opportunistically when present. Treat it as a nice-to-have, not a lever — further investment here (e.g. hand-tuning it beyond what's auto-generated) is low priority relative to the content-shape issues below.

## 3. RSL 1.0 Licensing — Not Present

## 4. Citability — Passage-Level Analysis

Content was analyzed against trafilatura's boilerplate-stripped extraction (not raw HTML with nav/footer chrome), per the skill's guidance, and cross-checked against actual DOM order to make sure nothing was mis-ordered by the extractor.

**Direct-answer framing: good.** Every FAQ answer sampled leads with the fact, not a preamble:
- "Marketing sites start at $900 and typically ship in 2–3 weeks..."
- "React and TypeScript on the frontend, Node.js and Express with MongoDB on the backend..."
- "Usually, because you're paying for one person's time rather than an account manager..."

**Passage length: below the citation sweet spot.** The skill's benchmark is 134–167 words for optimal AI-citation passage length. Measured actual answer lengths:

| Location | Answer | Word count |
|---|---|---|
| `/services` FAQ | "How much does a website or web application cost?" | 46 |
| `/services` FAQ | "How long does a project take?" | 36 |
| `/services` FAQ | "What technologies do you build with?" | 34 |
| `/services` FAQ | "Do you work with clients in other time zones?" | 38 |
| `/services` FAQ | "What happens after the project launches?" | 34 |
| `/blogs/custom-web-app-cost-2026` FAQ | "Is a freelance developer cheaper than an agency?" | 52 |
| `/blogs/custom-web-app-cost-2026` FAQ | "Why do quotes for the same brief vary so much?" | 28 |
| `/blogs/custom-web-app-cost-2026` FAQ | "What does ongoing maintenance cost?" | 38 |
| `/blogs/custom-web-app-cost-2026` FAQ | "Do you work across time zones?" | 30 |

Blog body sections show the same pattern — per-H2 word counts on `/blogs/react-performance-tips-2025` (10 numbered tips): 96, 90, 38, 77, 57, 84, 34, 30, 43, 58 words. Only 3 of 10 sections clear 80 words; none reach 134.

This isn't a structural defect — short, scannable sections are good for human skimming and for extracting a single crisp fact — but it means most individual passages are thinner than the range AI engines most often lift wholesale into a generated answer with attribution. The risk is fragmentary or paraphrased citation (engine reconstructs the answer from several thin fragments, sometimes losing the source link) rather than a clean quoted lift.

**No external citations found.** Both sampled blog posts (`react-performance-tips-2025`, `custom-web-app-cost-2026`) contain zero outbound links to any external source, standard, or reference (checked all `<a href>` tags inside the `<article>` body). All claims are self-authored/first-person ("I structure Express routes...", "My retainers start at..."), which is appropriate for opinion/experience content but weakens the page for platforms — Perplexity in particular — that favor content demonstrating evidence or cross-referencing of external sources. This is a content-authoring gap, separate from and not fixed by schema.

**Self-contained blocks: good.** FAQ answers and case-study blurbs read correctly in isolation without needing surrounding page context — a real strength for extraction.

**FAQPage schema is present** on `/services` and `/blogs/custom-web-app-cost-2026` (5 and 4 Q&A pairs respectively, confirmed via JSON-LD `@graph` inspection). Per current guidance, this should **not** be read as a confirmed AI-citation lever: Google retired FAQ rich results for all sites on 2026-05-07 (no SERP feature is generated from this markup any more), and there is no confirmed benefit to LLM citation from the schema itself — citability is driven by the visible text's structure and directness (covered above), not by the markup wrapping it. The schema is still useful for entity/E-E-A-T linkage (it ties `author`/`publisher` to the site's `Person`/`Organization` nodes) but shouldn't be treated as a citation feature in itself.

## 5. Structural Readability

- Single, correctly-ordered H1 on every sampled page, confirmed against actual DOM order (not just extracted text order — trafilatura's own extraction reordered one homepage paragraph ahead of the hero copy, which was checked and confirmed to be an artifact of the extractor's boilerplate-removal heuristic, not a real DOM/rendering problem — the live H1 and hero paragraph render first, as expected).
- Heading hierarchy is clean and logical throughout (H1 → H2 → H3, no skipped levels found in the 5 pages sampled).
- Question-phrased headings exist but are concentrated in only two places: `/services` ("How much does a website or web application cost?", "Do you work with clients in other time zones?", etc.) and `/blogs/custom-web-app-cost-2026` ("Is a freelance developer cheaper than an agency?", "Why do quotes for the same brief vary so much?"). The homepage, `/about`, and most other blog posts use topic-label headings ("Featured Projects", "Technologies I Work With", "1. Measure before you change anything") rather than natural-language question phrasing that matches how users actually query AI assistants.
- Numbered-list structure in how-to content (10 numbered tips in the React performance post, 4 numbered cost-driver factors in the cost post) aids extraction.
- The `/` and `/services` pricing sections use an actual `<table>` element (Package / Starting price / Typical timeline / Includes) rather than a div-based card grid rendered as prose — this is genuinely helpful, tables are one of the more reliably machine-parseable structures for extracting comparative facts.

## Top 5 Highest-Impact Changes

1. **Lengthen thin answer passages toward 134–167 words** (Effort: Low, ~1–2 hrs). The 9 FAQ answers sampled across `/services` and `/blogs/custom-web-app-cost-2026` run 28–52 words. Add one concrete sentence of specificity to each (a caveat, a worked example, a number) rather than padding with filler — pure content edit, no code/schema change needed.

2. **Add outbound citations to blog posts** (Effort: Low-Medium, ~30 min/post × 13 posts). Zero external links currently exist inside any sampled article body. Linking claims to primary sources (MDN, web.dev, React/Node docs, etc.) where relevant strengthens evidentiary citability specifically for Perplexity and Google AIO.

3. **Extend question-phrased headings beyond `/services` and one blog post** (Effort: Medium, ~half a day). Add a short 3–5 question FAQ block to the homepage, `/about`, and other high-intent blog posts, reusing the phrasing pattern already proven on `/services` ("How much does X cost?", "How long does Y take?") so more pages match natural-language AI queries.

4. **Build owned video/community presence** (Effort: Medium-High, ongoing). This is the single highest-leverage item per the correlation data (YouTube ≈0.737, the strongest AI-citation correlation in the skill's dataset, vs. Domain Rating ≈0.266). Even 1–2 short YouTube videos (a build walkthrough, a code review) linked from case studies/blog posts and added to the `Person`/`Organization` `sameAs` array would materially change the current entity-signal profile, which today has zero video presence. Genuine participation in r/webdev / r/reactjs linking back to specific articles is the second-best lever available (Reddit correlation also rated "High").

5. **Add an RSL 1.0 file** (Effort: Low, ~1–2 hrs). Declare AI training/reuse terms at `/rsl.xml`, generated alongside `llms.txt` in `scripts/prerender.mjs`. Low urgency (RSL adoption is still emerging) but cheap to add and complements the existing, already-correct robots.txt AI allow-list.

## What NOT to Prioritize

- Do not invest further hand-tuning effort into `llms.txt` beyond what's already auto-generated — it's ignored by Google Search and unconfirmed elsewhere; current auto-generated state is sufficient.
- Do not add or expand FAQPage schema expecting an AI/LLM citation lift from the markup itself — Google retired FAQ rich results 2026-05-07 (no SERP feature), and citability is driven by the underlying content structure covered in Section 4, not by the schema wrapper. Existing FAQPage instances are fine to keep (they still help the entity graph) but adding more won't move this score.
- Technical accessibility (Section 8) is already close to best-practice — no further work needed there before addressing Sections 4–7.
